# Handoff: BabyAI Transformer + NeuPSL implementation state

Timestamp: 2026-05-29 11:20:33 Asia/Shanghai

## Current Project State

The project has been refactored from the old MNIST demo into a BabyAI/MiniGrid
action-sequence prediction demo.

Current task:

```text
mission + symbolic observation + expert action history
  -> BabyAIPredictor
  -> next-action probabilities
  -> PSL / NeuPSL
  -> fused Action(S,A) predictions
```

The action space is:

```text
left, right, forward, pickup, drop, toggle, done
```

The main generated split currently used locally is:

```text
data/experiment_babyai/pretrain/size_0500-valid_0100
data/experiment_babyai/neupsl-train/size_0050-valid_0100
data/experiment_babyai/inference/size_1000
```

`data/experiment_babyai/` and `results/` are ignored by git.

## Data Generation

Entry point:

```text
scripts/create_data.py
```

Core modules:

```text
data/sequence_extraction.py
data/rule_extraction.py
```

Data generation uses BabyAIBot when MiniGrid is available:

```text
minigrid.utils.baby_ai_bot.BabyAIBot
```

Current split design:

```text
pretrain envs:
  BabyAI-GoToObj-v0
  BabyAI-Pickup-v0

neupsl-train / inference envs:
  BabyAI-PickupLoc-v0
  BabyAI-OpenDoor-v0
```

Only successful, non-truncated episodes of length at least 3 are kept. Data
scale is counted by episode, then expanded to step-level next-action samples.
History actions are the expert prefix, not model rollouts.

Step input format:

```text
[CLS] mission [SEP] symbolic observation [SEP] history actions [SEP]
```

The model uses token ids, type ids, and position ids.

## Rule Extraction

Runtime rule observations are currently derived in `data/rule_extraction.py`.

Predicates:

```text
InvalidAction(Step, Action)
PlausibleAction(Step, Action)
```

Examples:

```text
front_type == wall
  -> InvalidAction(step, forward)

front_type == door and front_state == closed
  -> PlausibleAction(step, toggle)

mission_kind == pickup and front_type == target_type
  -> PlausibleAction(step, pickup)
```

Generated files:

```text
invalid-action-*.txt
plausible-action-*.txt
rule-library.json
psl-rules.txt
```

The data exploration notebook now also demonstrates broader legal-rule candidate
mining from expert trajectories: it turns symbolic features into predicate
combinations and reports support/confidence/coverage for candidate
`PlausibleAction` rules. Those mined candidates are explanatory at present and
are not yet automatically promoted into runtime PSL facts.

## PSL / NeuPSL Implementation

PSL template:

```text
psl/rules/experiment__babyai.json
```

Rules:

```text
1.0: NeuralAction(S, A) -> Action(S, A) ^2
1.0: InvalidAction(S, A) -> ~Action(S, A) ^2
1.0: PlausibleAction(S, A) -> Action(S, A) ^2
Action(S, +A) = 1 .
```

Important implementation detail:

```text
runtime.db.intids = false
```

This is needed because PSL arguments include action ids as string-like values in
runtime output.

`psl/runner.py` builds concrete configs. It combines train and inference entity
maps for the DeepPredicate and writes:

```text
results/babyai_train_50_infer_1000/psl-config.json
```

DeepPredicate bridge:

```text
models/deeppsl.py::BabyAIActionModel
```

The bridge maps PSL step ids back to:

```text
entity-data-map.txt  -> token_ids + label
entity-type-map.txt  -> type_ids
```

Then it runs `BabyAIPredictor` and returns 7-way probabilities for
`NeuralAction(S,A)`.

NeuPSL learning sends PSL rule gradients back through this bridge and saves the
fine-tuned neural checkpoint to:

```text
results/babyai_train_50_infer_1000/model.pt
```

Final PSL fused atoms are stored in:

```text
results/babyai_train_50_infer_1000/runtime-output.json
```

## Scripts

Generate data:

```bash
python scripts/create_data.py \
  --pretrain-size 500 \
  --pretrain-valid-size 100 \
  --train-size 50 \
  --valid-size 100 \
```

```bash

  --pretrain-size 500 \
  --pretrain-valid-size 100 \
  --epochs 20 \
  --batch-size 64
```

```bash
python scripts/neupsl_train.py \
  --train-size 50 \
  --valid-size 100 \
  --inference-size 1000 \
```

```bash
python scripts/evaluate.py \
  --train-size 50 \
  --valid-size 100 \
  --inference-size 1000
```

## Recent Fixes / Decisions

- `models/transformer.py` sets `enable_nested_tensor=False` to avoid a PyTorch
  MPS nested tensor op that is not implemented.
- Training and inference visualizations use `Neural` and `NeuPSL`, not
  `pre/after`.
- Training demo visualizes episode endings rather than cherry-picked improved
  windows.
- Inference demo now parses true PSL fused `Action` atoms, not only the
  fine-tuned neural checkpoint.
- Inference visualization selects different action targets rather than showing
  only open-door examples.

## Open Technical Questions

- Whether to promote mined legal-rule candidates into runtime PSL facts
  automatically, and what thresholds or validation protocol to use.
- Whether to expose mission `instrs` directly to the Transformer, or keep the
  current surface mission plus symbolic observation representation.
- Whether to add more BabyAI environments to create richer goal/action variety,
  especially true drop/put-next tasks instead of rare incidental `drop` actions.
- Whether final reporting should focus on NeuPSL checkpoint accuracy, PSL fused
  `Action` accuracy, or both, since they measure different surfaces.
