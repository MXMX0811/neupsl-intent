## Recent Training Observations

The completed training demo showed:

- PSL `Final Objective` decreases during training.
- Transformer digit accuracy does not clearly improve.
- Final `ImageSum` categorical accuracy is about `0.1972`.
- Learned PSL rule weights remain effectively unchanged in the observed run.
- `NeuralClassifier` runtime atoms should be interpreted as Transformer/DeepPredicate digit probabilities, not separate PSL-fused digit labels.
- `ImageSum` atoms are the main PSL-fused addition outputs.

Likely causes to investigate:

- The PSL objective can decrease by changing continuous `ImageSum` variables without improving digit argmax accuracy.
- `gradientdescent.stepsize` in `psl/rules/experiment__mnist-1.json` is currently `1.0e-14`, which may nearly freeze rule-weight learning.
- PSL gradients to the neural predicate are logic-derived hinge-loss gradients, not supervised cross-entropy gradients, so they can be noisy or poorly aligned with digit accuracy.
- Current rules may not strongly or cleanly push useful corrections back into the Transformer.

## Trace and Checkpoints

Trace logging has been removed from the default code path.

The project no longer writes:

```text
training_trace.jsonl
```

Intermediate model state is now represented by checkpoint files:

```text
results/<run_id>/checkpoints/step_*.pt
```

`models/deeppsl.py` automatically resumes from the latest `step_*.pt` in the configured checkpoint directory when running learning again.

Rationale:

- The default demo path `results/train_1000_infer_5000/` stays clean.
- All experiment artifacts can be removed with one directory delete:
  `experiments/neupsl_tuning/`.
- Temporary rule templates and run configs stay close to the outputs they
  produced.
- The experiment script can still reuse the existing project modules:
  `DatasetConfig`, `PSLRunner`, `load_checkpoint`, and `utils.io`.

## Proposed Script

Create:

```text
experiments/neupsl_tuning/scripts/tune_neupsl.py
```

The script should:

- Read prepared data from the existing canonical data directories.
- Require an existing pretrained checkpoint, default:
  `ckpt/pretrained-transformer.pt`.
- Generate one temporary PSL rule/config JSON per run when rule-learning options
  need to differ.
- Run `PSLRunner.build_config()` and `PSLRunner.run_runtime()` for each run.
- Save step checkpoints every 10 NeuPSL gradient steps.
- Resume a run if its `checkpoints/step_*.pt` files already exist.
- Write per-run `metrics.json`.
- Write global `summary.csv` and `summary.json`.

Do not move the tuning loop into `notebooks/02_training_demo.ipynb`.
The notebook should remain a single-run explanatory demo.

## Experiment Recovery and Results

After a machine crash during the first long experiment, the isolated experiment
directory was recovered. The `baseline_wlr1e-14` run completed and contained:

```text
experiments/neupsl_tuning/results/baseline_wlr1e-14/
├── checkpoints/step_0010.pt
├── checkpoints/step_0020.pt
├── checkpoints/step_0030.pt
├── model.pt
├── runtime-output.json
├── learned-rules.json
└── metrics.json
```

The original five-run 30-step matrix is too expensive for the current machine:
one 30-step run took roughly the full 20-minute budget and stressed the system.
Two lighter 10-step runs were added in:

```text
experiments/neupsl_tuning/configs/runs_quick.json
```

Current valid results:

| run_id | neural_lr | psl_weight_lr | steps | ImageSum acc | train digit acc | inference digit acc |
|--------|-----------|---------------|-------|--------------|-----------------|---------------------|
| baseline_wlr1e-14 | 1e-4 | 1e-14 | 30 | 0.3568 | 0.8160 | 0.8010 |
| quick_wlr1e-8 | 1e-4 | 1e-8 | 10 | 0.6356 | 0.8245 | 0.8160 |
| quick_nlr5e-5_wlr1e-8 | 5e-5 | 1e-8 | 10 | 0.6484 | 0.8310 | 0.8212 |

Preliminary interpretation:

- Increasing PSL `gradientdescent.stepsize` from `1e-14` to `1e-8` improves
  `ImageSum` accuracy dramatically in short runs.
- The 10-step runs perform better than the 30-step baseline, suggesting long
  NeuPSL fine-tuning may degrade the Transformer or over-optimize the PSL graph.
- Lowering neural learning rate from `1e-4` to `5e-5` gave the best observed
  result so far.
- Learned rule weights in the 10-step `1e-8` runs changed only at very small
  numeric scale in `runtime-output.json`, but PSL logs show the learned model
  weights around `0.196...` for several rules. Future scripts should parse
  learned-rule weights from `learned-rules.json` and/or the runtime learned model
  carefully.

Performance note:

- A 10-step run still takes about 8.7-9.2 minutes.
- Future testing should use 5-10 steps and one run per process, then analyze
  before launching additional runs.
- Avoid running the full five-run 30-step matrix on this machine.

## Digit-Focused Tuning Update

Additional focused runs were executed after the recovery pass. The goal was to
test whether NeuPSL can improve the Transformer digit classifier itself, not
only the PSL `ImageSum` atoms.

The pretrained checkpoint baseline was measured directly:

| model | train digit acc | inference digit acc |
|-------|-----------------|---------------------|
| `ckpt/pretrained-transformer.pt` | 0.8280 | 0.8180 |

Updated valid experiment summary:

| run_id | neural_lr | psl_weight_lr | ADMM | steps | supervised CE | ImageSum acc | train digit acc | inference digit acc | seconds |
|--------|-----------|---------------|------|-------|---------------|--------------|-----------------|---------------------|---------|
| baseline_wlr1e-14 | 1e-4 | 1e-14 | 50 | 30 | 0.0 | 0.3568 | 0.8160 | 0.8010 | n/a |
| quick_wlr1e-8 | 1e-4 | 1e-8 | 50 | 10 | 0.0 | 0.6356 | 0.8245 | 0.8160 | 549.705 |
| quick_nlr5e-5_wlr1e-8 | 5e-5 | 1e-8 | 50 | 10 | 0.0 | 0.6484 | 0.8310 | 0.8212 | 523.839 |
| digit_admm25_nlr5e-5_wlr1e-8 | 5e-5 | 1e-8 | 25 | 10 | 0.0 | 0.3336 | 0.8310 | 0.8212 | 401.173 |
| digit_nlr2e-5_wlr1e-8 | 2e-5 | 1e-8 | 50 | 10 | 0.0 | 0.6568 | 0.8360 | 0.8202 | 487.250 |
| digit_nlr5e-5_wlr1e-7 | 5e-5 | 1e-7 | 50 | 10 | 0.0 | 0.6496 | 0.8310 | 0.8212 | 547.395 |
| digit_nlr2e-5_wlr1e-8_sup0p1 | 2e-5 | 1e-8 | 50 | 10 | 0.1 | 0.6572 | 0.8360 | 0.8202 | 698.891 |

Current best practical setting:

```text
neural_lr = 2e-5
psl_weight_lr = 1e-8
admm_iterations = 50
gradient_steps = 10
batch_size = 128
```

Interpretation:

- Lowering neural LR from `5e-5` to `2e-5` gave the clearest digit-classifier
  improvement: train digit accuracy rose from pretrained `0.8280` to `0.8360`.
- The corresponding inference digit accuracy only rose from `0.8180` to
  `0.8202`, so NeuPSL is improving the network only weakly outside the train
  entity set.
- Reducing ADMM iterations from 50 to 25 reduced runtime but collapsed
  `ImageSum` accuracy from about `0.65` to `0.33`, so ADMM=25 is not a good
  tradeoff for this setup.
- Increasing PSL `gradientdescent.stepsize` from `1e-8` to `1e-7` did not
  materially improve digit accuracy.
- Adding a small optional supervised CE anchor (`supervised-loss-weight=0.1`)
  did not improve digit accuracy beyond the pure `2e-5/1e-8` run; it only
  nudged `ImageSum` from `0.6568` to `0.6572` and increased runtime.
- The main remaining bottleneck appears to be the quality/alignment of the
  logic-derived gradients, not simply neural update stability.

Code changes made for this pass:

- `experiments/neupsl_tuning/scripts/tune_neupsl.py` now merges existing
  successful `metrics.json` files into `summary.csv/json` so new focused runs do
  not erase earlier valid rows.
- `experiments/neupsl_tuning/configs/runs_digit_focus.json` contains the focused
  tuning runs above.
- `models/deeppsl.py` supports an optional `supervised-loss-weight` option. The
  default is `0.0`, so existing demo/training behavior is unchanged unless an
  experiment explicitly sets it.

Next recommended experiment direction:

- Inspect misclassified digit pairs where PSL fixes `ImageSum` but the
  Transformer argmax remains wrong; this should reveal whether the rules are
  changing confidence without crossing argmax boundaries.
- Try rules or losses that provide sharper digit-level supervision, because
  current addition constraints are underdetermined: many digit pairs can explain
  the same sum.
- Keep ADMM at 50 for now and avoid long 30-step runs unless checkpoint curves
  show continued digit improvement.
