# Handoff: BabyAI migration planning

Timestamp: 2026-05-28 10:34:18 Asia/Shanghai

## Current Direction

The project should move from the current MNIST Addition demo to a BabyAI-based
behavior prediction demo while keeping the existing high-level repository
layout.

The target task is:

```text
current state + mission + action history -> Transformer/BabyAIPredictor -> action probability soft label
Transformer soft label + PSL rules -> PSL-fused action prediction
NeuPSL fine-tuning -> improved low-data/new-rule behavior prediction
```

This is no longer intended to be a general MNIST Addition project. MNIST APIs,
parameters, paths, predicates, notebooks, and documentation should be removed or
renamed as part of the BabyAI migration.

## Revised Requirements From AGENTS.md

Do not make a large structural redesign. Keep the current directory style:

```text
data/
models/
psl/
scripts/
notebooks/
utils/
docs/
```

But replace the MNIST task with BabyAI action prediction.

Important revised requirements:

- `data/generator.py` should not remain.
- All action-sequence extraction logic should live in:

```text
data/sequence_extraction.py
```

- All rule extraction and rule-library construction should live in:

```text
data/rule_extraction.py
```

- `scripts/create_data.py` should orchestrate dataset construction by calling
  the extraction modules. It can remain in `scripts/` as the user-facing entry
  point, because this matches the current project workflow.
- Remove MNIST-only API concepts such as `overlap`, `num_digits`, `max_sum`,
  `ImageSum`, `NumberSum`, and `PossibleDigits`.
- Rename the neural model from `MNISTTransformerClassifier` to a BabyAI-focused
  predictor, preferably:

```text
BabyAIPredictor
```

- Keep the three notebooks conceptually:
  - data exploration,
  - training demo,
  - inference demo.
- Update data exploration to show extracted action sequences and rule formats.
- If feasible, add BabyAI scene/episode visualization and action-sequence
  visualization.
- Use T-SNE or a similar projection to show distribution differences across
  pretraining, NeuPSL fine-tuning, and inference splits.

## Dataset Size Plan

Pretraining:

- 200-500 action sequences for training.
- About 100 action sequences for validation.
- 50-100 rules in the pretraining rule library.
- Train and validation should not overlap, but should come from the same
  distribution.

NeuPSL fine-tuning:

- About 50 action sequences for training.
- About 100 action sequences for validation.
- Add about 10 new rules that correspond to the NeuPSL split and are different
  from the pretraining-only rules.
- The NeuPSL rule library should include both pretraining rules and these new
  rules.
- NeuPSL train/valid should not overlap and should share a distribution.
- The NeuPSL distribution should differ from the pretraining distribution so
  fine-tuning effects can be observed.

Inference:

- About 1000 action sequences.
- Inference distribution should match the NeuPSL fine-tuning distribution.
- Inference should use the same rule library as NeuPSL fine-tuning.

## BabyAI Action Space

Standard BabyAI/MiniGrid action space is small, usually seven actions:

```text
left
right
forward
pickup
drop
toggle
done
```

Therefore the first BabyAI demo should be treated as a simple closed-domain
classification task rather than a decomposed action-argument prediction task.

In PSL, action mutual exclusivity should be enforced with a categorical/simplex
constraint:

```text
Action(Step, +ActionName) = 1 .
```

This avoids the complexity of verb/object/argument decomposition in the first
implementation.

## Rule Sources

Rules should come primarily from two reliable sources.

### Environment Dynamics Rules

These come from MiniGrid/BabyAI mechanics and are the safest rules:

```text
WallAhead(t) -> not Action(t, forward)
DoorAhead(t) & Closed(t, door) -> Action(t, toggle)
LockedDoorAhead(t) & not HasMatchingKey(t) -> not Action(t, toggle)
ObjectHere(t, obj) & MissionPickup(obj) -> Action(t, pickup)
CarryingTarget(t) & MissionPickup(obj) -> Action(t, done)
```

### Task Semantics Rules

These come from parsing BabyAI mission strings:

```text
MissionGoTo(obj)
MissionPickup(obj)
MissionOpen(door)
TargetColor(obj, red)
TargetType(obj, ball)
```

Example rules:

```text
MissionGoTo(obj) & AtAgentNear(obj, t) -> Action(t, done)
MissionPickup(obj) & AtSameCell(obj, t) & EmptyHand(t) -> Action(t, pickup)
MissionOpen(door) & DoorAhead(door, t) & Closed(t, door) -> Action(t, toggle)
```

Avoid relying on purely statistical rules from trajectories in the first pass.
Those can encode expert-policy preference rather than environment/task
constraints.

## Recommended Model Shape

Replace `MNISTTransformerClassifier` with:

```text
BabyAIPredictor
```

Suggested input representation for the first pass:

```text
[mission tokens] [SEP] [symbolic observation tokens] [SEP] [history action tokens]
```

The output should be:

```text
7-way action logits/probabilities
```

The first version should not require raw image/grid visual encoders. Symbolic
tokens are enough to test the NeuPSL interface and rule integration.

### Tokenization Update

Avoid building a large flat vocabulary with heavy prefixes such as:

```text
m_red
target_color_red
front_ball_red
hist_forward
```

This is easy to inspect but makes the vocabulary grow quickly and prevents the
model from naturally sharing concepts like `red`, `ball`, or `forward` across
mission, observation, target, and history contexts.

Prefer a field-aware representation:

```text
token_id + type_id + position_id
```

Example:

```text
tokens:
[CLS] pick up red ball [SEP] agent facing east front ball red empty hand target ahead [SEP] forward left [SEP]

types:
SPECIAL MISSION MISSION MISSION MISSION SPECIAL OBS_AGENT OBS_AGENT OBS_AGENT OBS_FRONT OBS_FRONT OBS_FRONT OBS_CARRYING OBS_CARRYING OBS_TARGET OBS_TARGET SPECIAL HISTORY HISTORY SPECIAL
```

The model embedding should combine:

```python
x = token_embedding(token_ids) + type_embedding(type_ids) + position_embedding(position_ids)
```

Recommended first-pass token types:

```text
SPECIAL
MISSION
OBS_AGENT
OBS_FRONT
OBS_TARGET
OBS_CARRYING
OBS_WORLD
HISTORY
```

The Transformer vocabulary should remain compact and reusable:

```text
red, blue, green, ball, key, door, wall, empty, locked, open,
agent, facing, front, target, carrying,
left, right, forward, pickup, drop, toggle, done
```

PSL should still use structured predicates such as `MissionPickup(Step, ball,
red)` and `ClosedDoorAhead(Step)`. The compact token/type representation is for
the neural model only.

## PSL / DeepPredicate Migration

Replace MNIST-specific predicates:

```text
NeuralClassifier(ImageId, Digit)
ImageSum(ImageId1, ImageId2, Sum)
NumberSum(X, Y, Z)
PossibleDigits(X, Z)
```

with BabyAI predicates such as:

```text
Action(StepId, ActionName)
NeuralAction(StepId, ActionName)
WallAhead(StepId)
DoorAhead(StepId)
ClosedDoorAhead(StepId)
LockedDoorAhead(StepId)
HasMatchingKey(StepId)
ObjectHere(StepId, ObjectType, Color)
MissionGoTo(StepId, ObjectType, Color)
MissionPickup(StepId, ObjectType, Color)
MissionOpen(StepId, Color)
AtTarget(StepId)
CarryingTarget(StepId)
```

The exact predicate names can be adjusted, but the rule template should live
under:

```text
psl/rules/experiment__babyai.json
```

`models/deeppsl.py` should expose a BabyAI DeepModel bridge, for example:

```text
BabyAIActionModel
```

Its responsibilities remain the same:

- return neural action probabilities to PSL,
- receive PSL gradients,
- backpropagate through `BabyAIPredictor`,
- save and load checkpoints.

## Script Responsibilities

Keep the script entry points:

```text
scripts/create_data.py
scripts/pretrain_transformer.py
scripts/neupsl_train.py
scripts/evaluate.py
```

But retarget them to BabyAI:

- `create_data.py`: orchestrates split creation, calls
  `data.sequence_extraction` and `data.rule_extraction`.
- `pretrain_transformer.py`: supervised action prediction pretraining.
- `neupsl_train.py`: BabyAI NeuPSL fine-tuning.
- `evaluate.py`: action accuracy, PSL-fused accuracy, rule violation rate, and
  runtime summary.

## Suggested First BabyAI Scope

Use one small BabyAI/MiniGrid family first, not the full task suite.

Good candidates:

- `GoToObj`
- `PickupObj`
- a similarly simple BabyAI level with stable expert trajectories

The first implementation should focus on next-action prediction:

```text
input: mission + symbolic current observation + action history
label: expert next action
```

Do not make PSL responsible for full planning in the first pass. PSL should act
as a structured correction/regularization layer over Transformer action
probabilities.

## Metrics To Collect

Minimum metrics:

- Transformer-only action accuracy.
- PSL-fused action accuracy.
- Rule violation rate.
- Low-data pretrain vs NeuPSL fine-tune change.
- New-rule split performance.
- Runtime, especially NeuPSL fine-tuning duration.

Fine-tuning should be kept around 5-10 minutes.

## Open Design Questions

Need to decide before implementation:

- Which exact BabyAI/MiniGrid environment to use first.
- Whether expert action sequences come from a built-in expert, a scripted
  shortest-path expert, or generated symbolic demonstrations.
- How much observation detail to tokenize in v1.
- Whether `Action` and `NeuralAction` should be separate predicates or whether
  the DeepPredicate should continue using the existing `NeuralClassifier` name
  for less PSL config churn.
- How to implement negative rule effects in PSL cleanly: explicit invalid
  observation predicates may be easier than relying on complex negation.

## Revision v3 Decisions

The main technical route is now considered settled.

Dataset scale should be counted by episode/trajectory, not by step sample.
During training, successful episodes are split into step-level or segment-level
next-action prediction examples.

Short trajectories should be filtered:

```text
success == true
len(actions) >= 3
not truncated
```

The project should not use autoregressive recursive prediction for the primary
training/evaluation path. History actions should come from the expert prefix,
not from previous model predictions.

Initial BabyAI split:

```text
pretrain:
  BabyAI-GoToObj-v0
  BabyAI-Pickup-v0

neupsl-train + inference:
  BabyAI-PickupLoc-v0
  BabyAI-OpenDoor-v0
```

Initial observation token scope:

```text
agent facing <dir>
front <empty|wall|door|key|ball|box>
front color <color>
front state <open|closed|locked>
hand <empty|key|ball|box>
hand color <color>
target <type> <color>
target relation <ahead|left|right|behind|unknown>
target distance <near|mid|far|unknown>
mission kind <goto|pickup|open>
```

Full-grid tokenization should be deferred until the first compact-symbolic
pipeline works.

The first rule extraction strategy should use derived facts:

```text
InvalidAction(Step, Action)
PlausibleAction(Step, Action)
```

with simple PSL rules:

```text
InvalidAction(S,A) -> ~Action(S,A)
PlausibleAction(S,A) -> Action(S,A)
Action(S,+A) = 1 .
```

The PSL-side neural and fused outputs should be separate:

```text
NeuralAction(Step, Action)  # DeepPredicate / Transformer output
Action(Step, Action)        # PSL-fused action output
```

NeuPSL fine-tuning should first follow the original NeuPSL mechanism. Add an
explicit ground-truth/supervised anchor only if the initial logic-derived
gradient is too weak.

Initial `BabyAIPredictor` configuration:

```text
max_seq_len = 96
embedding_dim = 64
num_layers = 2
num_heads = 4
dropout = 0.1
pooling = CLS token
classifier = Linear/ReLU/Linear
```

Entity data should use separate token and type maps:

```text
entity-data-map.txt
203    1 14 15 16 17 2 40 ... 0    3

entity-type-map.txt
203    0 1 1 1 1 0 2 ... 0
```

The system should be updated so the neural model reads both maps and combines:

```python
token_embedding(token_ids) + type_embedding(type_ids) + position_embedding(pos_ids)
```

Mission input should support:

```text
mission_encoding = "surface" | "structured"
```

`surface` uses the natural-language mission string. `structured` uses tokens
derived from `env.unwrapped.instrs`. The first implementation should support
the option even if one mode is used as the default.
